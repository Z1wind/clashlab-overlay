# ClashLab 局限性（2026-11-27 诚实版）

## 识别 / 数据
1. **不能自动识别建筑位置**：检测器（CenterNet/滑窗分类器）在真实战图上失败；真实阵必须人工标注（4 角 + 建筑）。
2. **自动标定不可靠**：草地轮廓/蓝墙连通域/Hough/quad_model 在侦察视角全部失败，只能交互式点四角。
3. **无 API**：ClashKing 明确拒绝（模拟器+覆盖层 ToS 灰区），拿不到对手布局/TH/部落战数据；OCR 对手名只能做本地显示。
4. **数据小**：实战验证仅 6 套 TH16 阵；TH1–19 数值为静态近似；TH17 新建筑（如 firespitter）缺战斗参数。

## 算法
5. **评分是启发式**：指标权重未经真实防守数据校准；墙若用折线标注，隔间/墙效率会失真。
6. **穿云箭落点敏感**：98 例压测仅 26% 落点稳定、±0.5 格会翻转目标；无攻击仿真二次校验。
7. **无对局推演**：没有兵种寻路/伤害模拟，2D 推演只是启发式，不是真战斗结果。

## 工程 / 交付
8. **平台**：Windows 覆盖层 + Android 标注器；无 iOS/macOS/网页版。
9. **体积**：exe 约 121 MB（RapidOCR/onnx 内置）；未做代码签名（SmartScreen 会提示）。
10. **测试**：315 单测绿，但没有端到端自动化；UI 回归靠脚本人工看截图。
11. **无后端**：无云同步/账号/多人协作；数据都在本地。

## 合规
12. **ToS 灰色地带**：模拟器与覆盖层在部分场景可能违规；不宜公开推广、不可用于赛事。README 已写免责声明。

# 没有 API 之后怎么做（本地优先路线）

## 原则
只做**单机、只读、本地数据**能闭环的东西：截图 → 标定 → 结构 → 分析 → 战术。
不碰游戏内存/点击/网络，不依赖第三方授权。

## P0：把「标注」从 3 分钟降到 30 秒（半自动标注）
- 分类器先在 44×44 网格上出**候选建筑**（已有 type+level 模型），UI 上只让用户点「对/错」两下确认
- 关键：把用户确认结果**反哺**成真实训练数据（含负样本），这是目前唯一能积累标注的路径
- 验证指标：同一阵标注耗时 <60s；候选召回 ≥70%、误报 ≤30%（人工修正后）

## P0：标定交互化
- 用户点第一角 → 搜索附近墙线做吸附；点完 4 点用 RANSAC 拟合 44×44 格点，实时显示网格对齐度
- 验证：6 套已标注阵的 quad 与人工 quad 误差 <0.5 格

## P1：评分规则化（借鉴 danielholmes/coc-base-analyser）
- 把启发式权重改成**可解释规则集**（大本是否被墙包、防空是否覆盖核心、隔间是否 >N、入口偏移等）
- 输出「违反规则清单 + 修改建议」，而不是一个黑箱分数

## P1：布局数据层（借鉴 koniz-dev/clash-blueprint-engine 的思路）
- 44×44 布局改为**逐格墙体网格** + 建筑占格，支持导入/校验/回放/差异对比
- 好处：墙类指标（隔间/开口/引导）才能真正算对

## P2：战术工具（不需要 API）
- 兵种/法术配比规划器（基于 TH 与兵种数据表）
- 穿云箭交互规划器：用户点 3 个点 → 实时方向/命中预览（已有内核）
- 防守自检：导入自己的阵，一键出弱点和修复建议

## P2：数据积累
- 每标注 1 阵自动入库（含截图 + 布局 + 来源），形成自有数据集；100 阵后重训检测器做 domain adaptation

## 不做的
- 不追 API/token、不碰自动化操作游戏（自动点击/自动开战）、不做账号代打
