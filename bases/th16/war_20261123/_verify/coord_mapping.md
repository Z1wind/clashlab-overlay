## 1. 截图类型判定：**整窗抓屏（含模拟器 chrome），不是客户区截图**

证据（像素实测，非估）：

| chrome 成分 | 实测 | 说明 |
|---|---|---|
| 顶部标签栏（雷电模拟器/部落冲突 tab） | 高 ≈33–48px，藏青实色 BGR≈(41,31,31)，行占比 ≥0.98 | 客户区截图不可能含此条 |
| 底部黑底栏 | 高 ≈11–20px，近黑 (0,0,0)，行占比 =1.0 | 同上 |
| 右侧竖排按钮导轨 | 宽 ≈25–29px，暗实色列占比 ≥0.95（音量/剪刀/RPK/录屏图标列） | 同上 |
| 图幅 | 1040–1051 × 603–628，均 ≠ 1000×563 | 客户区截图应正好 1000×563 |

结论：截图工具对雷电**整窗抓屏**（标题栏+客户区+导轨一起进图），未裁客户区、未按客户区缩放。
因此**图片里的标定结果不能直接装到覆盖层**：直接用会整体偏移（顶部多算标签栏、右侧多算导轨），必须先去 chrome 再归一化。

## 3. 变换公式（P2 修正后）

设图片像素 (px, py)，表面矩形 (L,T,R,B)：

```
u = (px - L) / (R - L)          # 表面内归一化 [0,1]
v = (py - T) / (B - T)
```

渲染空间 1280×720（draw.py 口径）：`rx = 1280·u, ry = 720·v`。
客户区 **1000×563**（sx=1000/1280, sy=563/720）：

```
cx = u · 1000 = (px - L)/(R - L) · 1000
cy = v · 563 = (py - T)/(B - T) · 563
```

即**图片→客户区 = 先表面归一化，再分别乘 1000 / 563**；无独立 x/y 偏移（偏移已含在 L/T 里）。
反向（客户区→图片）：`px = L + u·(R−L)`，`u = cx/1000`；`py = T + v·(B−T)`，`v = cy/563`。

**屏幕原点不写死**：RenderWindow 客户区原点随窗口挪动变化（实测先后出现 (202,184)、(177,252)、(159,255)，尺寸恒 1000×563）。运行时由 `runtime.py` 每帧 `ClientToScreen+GetClientRect` 自同步（日志 `overlay rect sync -> client=(x,y,1000x563)`），覆盖层窗口跟随；本文件只锁归一化公式与 1000×563 尺寸，**任何具体屏幕原点都只是某次采样，禁止写死进公式**。屏幕坐标 = 当次实测原点 + (cx, cy)。

## 4. 回答

- **能不能直接装？** 不能。整窗抓屏含 chrome，直接用图片坐标 = 顶部/右侧整体内缩错误。
- **需要什么变换？** 按 §2 表面矩形归一化 → §3 公式映射到 1000×563 客户区；P1 的 44×44 网格先在图片空间标定，再经此公式出客户区版本（`_verify/<slot>_grid_client1000.png`）。
- 客户区网格图（`*_grid_client1000.png`）一律以客户区本地 (0,0) 原点出图，不带任何屏幕偏移；屏幕位置由运行时自同步叠加。
- 注意：本变换只解决「图→客户区」口径；菱形透视/遮挡导致的定标误差由 P1 逐点误差单独判定。
